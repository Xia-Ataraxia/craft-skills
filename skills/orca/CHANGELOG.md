# Changelog — orca

- 2026-09-05 — v1.0.0: a shell could not tell which layer of an Orca connection had failed, so a registration fault read as a network fault and a dead remote runtime read as a transport fault → seeds `SKILL.md` with a four-layer verify-and-repair contract (CLI presence, repo registration, remote-runtime liveness, SSH transport), a surface-to-layer map, a symptom index, and one `## Anti-patterns` registry. Admission evidence: the bundled upstream `orca-cli` guide carries the command inventory but no failure-mode diagnosis — a scan found zero occurrences of `selector_not_found`, `remote_runtime_unavailable`, `RemoteCommand`, `ControlPersist`, or crash-handler false positives, and its only ssh mention warns that forwarded invocations break skill-sharing discovery — so this package owns the repair layer and hands usage back to that guide. Boundary: `tailscale` keeps tailnet-layer reachability and disclaims generic ssh configuration problems, so the `RemoteCommand` and `ControlPersist` traps land here; `browser` keeps live-browser backends; `git` keeps plain git worktrees against Orca-managed ones. Named as a plain noun per contract §2, governing a platform surface rather than an action, matching the `tailscale` and `git` precedents. Corpus: `tests/orca/evals/evals.json` covers an unregistered sibling checkout, a remote host verdict, both ssh transport traps, and a cannot-succeed case where process listings contradict `orca status`; `tests/orca/evals/triggers.json` pairs 8 should-trigger prompts with 8 near-misses drawn from `tailscale`, `git`, `browser`, `debug`, `defuddle`, and `vmware`.
- 2026-09-13 — v1.1.0: repeated grouping, identity, and cleanup corrections exposed avoidable operator load → adds [low-clutter operations](references/operations.md), bounds non-interactive verification, preserves four-layer diagnosis, and expands scenario and routing coverage; verified_against: orca@1.4.200, git@2.50.1, openssh@10.3p1 (capability/configuration probes and operator-session evidence, not a new destructive replay). Provenance: operator-supplied Orca operating conversation, generalized without private transcript, account identifiers, or host paths; [official worktree model](https://www.onorca.dev/docs/model/worktrees), [Git branch semantics](https://git-scm.com/docs/git-branch), and [OpenSSH options](https://man.openbsd.org/ssh_config).
- 2026-10-01 — v1.2.0: copied connection command sheets and retired RPC and CLI recipes could contradict the installed guides, and a selector miss was being read as proof a repo was unregistered → keeps thick local naming, grouping, identity, ownership, and cleanup judgment; delegates executable usage, retries, liveness, settlement, and supervised release to the installed orca-cli and orchestration guides; diagnoses connection layers without automatic registration or app restart; accounts for task-owned terminals without blanket closure. Provenance: official installed orca@1.4.215 `orca-cli` and `orchestration` guides, fetched read-only from the selected executable. Not a vendor fork.
- 2026-10-06 — v1.2.1: a guide was read from wherever it was found, so a stale or absent installed skill could shadow the version-matched bundled guides, and a skill refresh was being read as an application or remote-host upgrade, restart, or pairing → reads the selected executable's version-matched bundled guides first (`orca skills list`, `orca skills get <name>`); installs or updates a task-relevant official skill through the official channel only when absence or staleness is proven and the effect is separately authorized, verifies the result, otherwise no-ops; keeps skill refresh distinct from application or remote-host upgrade, restart, and pairing. verified_against: orca@1.4.220 (observed via `orca --version` and `orca skills update --help`).
- 2026-10-09: PARA lifecycle groups split a product's repositories across buckets, so the sidebar hid which repositories are worked on together; grouping now defaults to the domain or large project and keeps an operator's existing layout until asked to regroup. A setup added to a paired runtime also stored a host id unlike that runtime's other setups while reading ready, so the inventory now reads the host id back.
- 2026-10-09: Review found a shared owner, organization, or parent folder could merge unrelated products into one group, so those signals now only nominate a candidate that the operator's wording or a cross-repository contract must confirm.
- 2026-10-09: The body restated what the official skills own and buried the operator-specific judgment; it is now a thin router to the official skills (bundled guide or `npx skills add`) plus boundaries, report shape, one connection-layer table, and anti-patterns. Adds the docs-and-issues-first rule and the remote-only grouping note after a grouping failure was guessed at while an upstream issue already named the cause.
